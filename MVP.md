# MVP

Текущий этап проекта — минималистичный, но полностью рабочий MVP.

## Цель проекта

Создать:
- надёжное и тестируемое ядро складского учёта
- интеллектуальный интерфейс для приёмки и поиска
- архитектуру, готовую к масштабированию (много складов, отчёты, мониторинг)
- актуальную документацию 

## Текущий этап (MVP / Demo)

Реализуется минимально необходимый функционал для демонстрации:

### Ядро
- создание и удаление складов
- приёмка позиций
- перемещение позиций
- поиск позиций
- подсчёт остатков

### Интерфейсы
- CLI (основной инструмент разработки и тестирования)
- LLM-интерпретация:
  - текст
  - голос (через транскрипцию)
  - изображения (через мультимодальный LLM)

### Тестирование
- автоматические тесты ядра
- сценарные тесты (человеческие)
- каждый тест работает с новым, пустым складом

---

## Что НЕ входит в MVP
- авторизация и роли
- сложные диалоги и обучение
- отчёты и мониторинг
- UI / мобильные приложения

(но архитектура учитывает их появление)

---

## Основные принципы
- единый codebase, множество складов
- каждый склад полностью изолирован
- бизнес-логика не зависит от интерфейсов
- LLM — переводчик, а не исполнитель
- всё должно быть тестируемо без мессенджеров

## Error Handling (MVP)

На текущем этапе система использует упрощённую обработку ошибок.

Если ввод пользователя (текст, голос или изображение):
- не может быть однозначно интерпретирован
- приводит к невалидной или неполной команде
- вызывает сомнения в корректности действия

то:

- никакие изменения склада не выполняются
- команда в ядро не отправляется
- пользователю возвращается короткое уточняющее сообщение и 1–3 вопроса

Пример:

> "Не зовсім зрозуміло, скільки саме потрібно списати. Скажи кількість?"

Детальная классификация ошибок будет реализована на следующих этапах.
 
## Принцип работы

Система работает по строгому правилу:

- Если намерение пользователя понято — действие выполняется.
- Если намерение не понято или данных недостаточно — действие НЕ выполняется.

Система может задавать короткие уточняющие вопросы при недостатке данных.
Пока вопрос не закрыт — никаких команд в ядро не отправляется.

## Поддерживаемые операции

В MVP поддерживаются только следующие операции:

- добавить
- убрать
- узнать количество
- показать весь склад
- найти, где лежит предмет
- переложить предмет

Другие операции в MVP не существуют.

## Отказы

Если действие не может быть выполнено, система сообщает причину:
- что именно не было понято
- или почему действие невозможно (например, предмет отсутствует)

Система может задавать 1–3 коротких уточняющих вопроса вместо абстрактного «переформулюй».

## Дефолты

- количество не указано → 1
- локация не указана → null
- from_location не обязателен для операции перемещения
- пользователь всегда работает с одним складом
