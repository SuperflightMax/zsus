## Unit-тесты Core (pytest)
- Расположение: `tests/core/test_core_engine.py`
- Фреймворк: `pytest`
- Каждый тест создаёт свежие `CoreEngine` и `InMemoryStorageBackend`.
- Каждый тест работает с отдельным `storage_id` (например, `"test_storage"`), не полагаясь на глобальное состояние.
- Проверяются:
  - intake (новые предметы, массив предметов, повторный intake, невалидное qty)
  - move (между локациями, недостаток qty, отсутствие предмета)
  - consume (расход из локации, полное обнуление, недостаток qty)
  - find (одна/несколько локаций, отсутствие предмета)
  - list (пустой склад, несколько предметов и локаций)
  - изоляция складов
  - неизвестная команда
- Инварианты в каждом тесте:
  - ответы ядра имеют форму `{status, data|error}`
  - ошибки не меняют состояние склада
  - движок не падает на ошибочных входах

Запуск: `pytest tests/core`

## Сценарные тесты (CLI, JSON)
- Назначение: демонстрация, ручные проверки, массовые операции.
- Формат сценария (JSON-файл):
  ```json
  {
    "name": "scenario_name",
    "steps": [
      {
        "command": { "...": "..." },
        "expect": "ok" | { "status": "ok", "data": { "...": "..." } }
      }
    ]
  }
  ```
- `command` — JSON-команда ядру. `storage_id` подставляется активным складом CLI (или временным при `--isolated`).
- `expect`:
  - `"ok"` — ожидается `status == "ok"`;
  - объект — частичное совпадение ответа (поддерживается вложенность).

## Запуск сценариев через CLI
- Команда: `+runscenario <file>` — использует активный склад.
- Изоляция: `+runscenario --isolated <file>` — создаёт временный склад, активирует только на время сценария, затем удаляет.
- Вывод по шагам: номер шага, команда, результат, статус `OK/FAIL`. В конце: `Scenario PASSED/FAILED`.
- Ошибки сценария отображаются, но CLI остаётся рабочим.

Пример запуска:
```
bot:demo> +runscenario scenarios/example.json
bot> +runscenario --isolated scenarios/example.json
```
