# Core Command Contracts

## Связь команд ядра с пользовательским вводом

Команды, описанные в этом документе, являются командами ядра системы.

Пользовательский ввод и LLM-интерпретация никогда не формируют эти команды напрямую.
Перед выполнением каждая команда должна быть полностью сформирована и валидирована системой.

---

Все изменения состояния склада выполняются **только через ядро**
путём передачи структурированных команд.

Ядро не принимает:
- текст
- изображения
- аудио
- неструктурированные данные

---

## Общий формат команды

```json
{
  "storage_id": "string",
  "command": "string",
  "payload": { }
}
```
---

### Команда: create_storage

Создание нового склада (используется тестами и инфраструктурой).

```json
{
  "command": "create_storage",
  "payload": {
    "storage_id": "test_storage_1"
  }
}
```
---

### Команда: delete_storage

```json
{
  "command": "delete_storage",
  "payload": {
    "storage_id": "test_storage_1"
  }
}
```
---

### Команда: intake

```json
{
  "command": "intake",
  "payload": {
    "items": [
      { "item_id": "pm_pistol", "qty": 1, "location": "сейф в кабинете", "holder": "Сокіл +380..." },
      { "item_id": "9mm_ammo", "qty": 28, "location": null }
    ]
  }
}
```

Инварианты (MVP):
- `items` — непустой массив
- `qty` для каждой позиции — строго `> 0` (допускаються дробні значення)
- `location` может быть `null` (предмет без размещения)
- `holder` необязателен; свободная строка-заметка “у кого / за кем закреплено”
- `item_id` создаётся в справочнике при первом появлении
- `unit` (необов'язково) — строкове позначення одиниць виміру

---

### Команда: move

Перемещение предмета.

```json
{
  "command": "move",
  "payload": {
    "item_id": "radio",
    "qty": 2,
    "from": null,
    "to": "A1",
    "holder": "Сокіл +380..."
  }
}
```

Инварианты (MVP):
- `qty > 0` (допускаються дробні значення)
- предмет должен существовать и иметь достаточный остаток на `from`
- при отсутствии предмета или недостаточном остатке ядро возвращает ошибку
- локации `from` и `to` могут быть `null` (перемещение с/без размещения)
- `holder` необязателен; если поле присутствует, оно задаёт новую заметку на целевой позиции
- `holder: null` очищает заметку на целевой позиции
- если `holder` отсутствует, заметка не меняется специально

---


### Команда: consume

используется для:
выдачи предметов со склада
расхода без указания назначения
списания (в MVP — логически то же самое)

Это уменьшение количества, без добавления в другую локацию.

```json
{
  "command": "consume",
  "payload": {
    "item_id": "fuel_barrel",
    "qty": 3,
    "from": null
  }
}
```

from — локация, откуда расходуется
from = null — расход «просто со склада»

Поведение
проверить, что предмет существует
проверить, что в from достаточно количества
уменьшить количество
если после уменьшения qty == 0 → запись может быть удалена
не добавлять предметы никуда
holder не меняет поведение consume на уровне core

Ошибки
qty <= 0 → error
предмет не существует → error
локация не существует → error
недостаточно количества → error

### Команда: list

Возвращает полный слепок содержимого склада.

```json
{
  "command": "list",
  "payload": { }
}
```

Ответ

```json
{
  "status": "ok",
  "data": {
    "radio": { "null": { "qty": 1, "unit": "од", "holder": "Сокіл +380..." }, "box": { "qty": 2, "unit": "од" } },
    "battery": { "box": { "qty": 5, "unit": "од" } }
  }
}
```

Ключи в `data` — идентификаторы предметов. Для каждого предмета указаны локации, кількість (`qty`) та одиниці (`unit`); `null` означает предмет без размещения. Если у позиции есть заметка “у кого / за кем закреплено”, возвращается `holder`.

----

### Команда: find

Поиск предмета.

```json
{
  "command": "find",
  "payload": {
    "item_id": "radio"
  }
}
```

ответ

```json
{
  "status": "ok",
  "data": {
    "item_id": "radio",
    "total_qty": 10,
    "locations": {
      "null": 4,
      "tank_1": 6
    },
    "holders": {
      "tank_1": "Сокіл +380..."
    }
  }
}
```

null = «просто на складе»
total_qty = сумма по всем локациям

find возвращает все локации, где предмет присутствует
если у найденных позиций есть holder, find дополнительно возвращает `holders` по ключам локаций

если предмет не найден нигде → error

если найден:
агрегировать по всем локациям
вернуть полную картину

find ничего не меняет, только читает состояние.

---

### Ответ ядра (общий)

```json
{
  "status": "ok | error",
  "data": { }
}
```
Ядро не формирует человеко-читаемые тексты.
