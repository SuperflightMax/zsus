# CLI Commands (skeleton)

- `exit` — завершает работу CLI.
- `quit` — завершает работу CLI.

## JSON команды

- Если нет активного склада, JSON-команды запрещены (сообщение: `No active storage. Use +activatestorage first.`).
- Если ввод начинается с `{`, CLI переключается в режим сбора JSON: используется альтернативный промпт (`... ` по умолчанию), копятся строки.
- Сбор завершается, когда баланс фигурных скобок выравнивается или введена пустая строка.
- После этого CLI пытается распарсить собранный текст через `json.loads()`; если это dict — добавляется поле `storage_id` с активным складом и команда передаётся в `core.engine.handle_command`.
- Ответ ядра (dict) печатается в виде JSON.
- При ошибке парсинга выводится нейтральное сообщение, CLI остаётся в рабочем состоянии.
- Обычный текст, не начинающийся с `{`, выводится как есть (echo).

## Admin-команды (префикс `+`)

- `+createstorage <storage_id>` — создаёт новый склад (если уже существует — сообщение).
- `+deletestorage <storage_id>` — удаляет склад; если удаляется активный, активный сбрасывается.
- `+liststorages` — выводит список складов и помечает активный.
- `+listitems` — выводит содержимое активного склада в табличном виде (item, location, qty). Локация `null` отображается как `(unplaced)`. Длинные значения усекаются и дополняются `...` по `cli.table_max_width` (по умолчанию 24).
- `+activatestorage <storage_id>` — делает склад активным (ошибка, если склада нет).
- `+status` — выводит состояние CLI (активный склад, backend, количество известных складов).
- `+runscenario [--isolated] <file>` — выполняет шаги сценария из JSON-файла; `--isolated` создаёт временный склад, активирует его на время сценария и удаляет после завершения.

Backend выбирается конфигом (`storage.backend`): `memory` (по умолчанию) или `sqlite`
с именем файла `storage.sqlite_filename` (по умолчанию `storage.db`), который создаётся
в каталоге склада. Статус показывает текущий выбранный backend.

## Plain text flow

- Нормальный текст (не JSON и не admin-команда) отправляется в LLMInterpreter.
- Interpreter возвращает `intent`, `confidence`, `human_summary_ua`, `command` (или `null`).
- CLI выводит две секции:
  - SERVICE: intent, confidence, сформированный command JSON, ответ ядра (если вызван) или ошибки.
  - USER: только `human_summary_ua` (без JSON и ошибок).
  Разделитель:
  ```
  --- SERVICE --------------------------------
  ...json...
  --- USER -----------------------------------
  ...text...
  --------------------------------------------
  ```
- Команда выполняется только если `intent != unknown`, `command` не `null`, и `confidence` ≥ порога (`core.confidence_threshold`, по умолчанию 0.7). Иначе — только сообщение пользователю.
- Если нет активного склада, команды не исполняются, отображается предупреждение в USER.

## Prompt

Промпт формируется по шаблону `cli.prompt_template` (по умолчанию `bot{storage}> `):
- без активного склада: `bot>`
- с активным складом, например `sklad_fuel`: `bot:sklad_fuel>`
