# Code Architecture Guide

Этот документ описывает структуру кода и принципы,
которых необходимо придерживаться при разработке.

## Base language - PYTHON

## Общая структура проекта

```
src/
├─ core/ # бизнес-логика
├─ llm/ # интерпретация намерений
├─ media/ # аудио и изображения
├─ knowledge/ # доменные знания
├─ interfaces/ # CLI, боты, приложения
└─ infra/ # хранилища, registry
tests/
├─ core/
├─ scenarios/
└─ media/
```
---

## core/

Содержит **только бизнес-логику**.
```
- entities/
  - Item
  - Location
  - Movement
- services/
  - IntakeService
  - MoveService
  - SearchService
- repository/
  - StorageRepository
- engine.py
  - точка входа для команд
```
core не импортирует ничего из llm, media или interfaces.

## Жизненный цикл команды

В системе существует чёткое разделение между интерпретацией пользовательского ввода и выполнением действий.

### DraftCommand
DraftCommand — это промежуточное представление намерения пользователя.

- создаётся интерпретатором (LLM или другим интерфейсом)
- может быть неполным
- может содержать уровень уверенности
- НИКОГДА не исполняется напрямую

### ExecutableCommand
ExecutableCommand — это полностью валидированная команда, готовая к выполнению ядром.

- создаётся только системой
- всегда детерминирована
- содержит все необходимые параметры
- передаётся в core engine

Интерпретатор никогда не вызывает core напрямую.

## llm/

Отвечает за:
- интерпретацию текста
- работу с изображениями
- формирование предложений и команд
- fallback-ответы

- Interpreter
- IntentResolver
- ProposalBuilder
- ConfirmationState

## Storage backends

- По умолчанию используется `memory` backend (несохраняемый, как в тестах ядра).
- Для персистентности можно выбрать `sqlite` с конфигом:

```yaml
storage:
  backend: sqlite
  sqlite_filename: storage.db
```

SQLite backend создаёт отдельный файл базы для каждого склада в его каталоге
(`storages/<storage_id>/storage.db` по умолчанию), повторяя поведение
InMemoryStorageBackend без изменений core-логики.

## Основные запреты

- интерфейсы не содержат бизнес-логики
- LLM не вызывает core напрямую
- core не знает про LLM
- никакой логики «на глазок»
